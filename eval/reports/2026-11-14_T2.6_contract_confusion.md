# T2.6 — Contract engine confusion matrix (2026-11-14)

> **Synthetic agreements and constructed claims.** 200 claim–clause pairs (20 per synthetic agreement) with gold statuses set by construction from terms.yaml. Claims are passed as a user-confirmed agent with high ASR confidence and a confirmed quote, so the matrix isolates the contract engine (gates are tested separately). Real calls and lender documents will be harder; not the Phase 4 measurement.

- Pairs: 200. Status accuracy **193/200 (96.5%)**; status + reason code exact: 193/200.
- **CONFLICT precision 87/87 = 1.000** (target ≥ 0.90, doc 12 A.3); CONFLICT recall 87/88.

## Findings

1. **CONFLICT precision 1.000** (87/87): no MATCH, UNCLEAR or NOT_VERIFIED pair became a CONFLICT. Numeric pairs
   (same / different / rounding band / unit change / zero claims / GST inclusion / rate basis / conditional) are
   decided by the deterministic path with the doc 06 tolerance table and are all correct.
2. The 7 misses are all on the semantic path and are conservative: "no insurance charge" against documents that
   never mention insurance (gold NOT_VERIFIED, got UNCLEAR(semantic_disagreement) — the NLI model and the judge
   disagree on whether silence supports "no charge"); "the KFS is part of the agreement" (gold MATCH, got UNCLEAR —
   the clause says it "forms part of this Agreement" but one of the two checks didn't entail); and one Gemma judge
   call that failed → NOT_VERIFIED(engine_error), never MATCH.
3. NLI thresholds T_nli_contra = T_nli_entail = 0.5 (provisional; both checks must agree), recorded for HC-4.
4. A gold-construction error found on the first run (a +₹50,000 loan-amount difference is inside the ±3% rounding
   band on large loans) was fixed in the pair generator, not in the engine.
